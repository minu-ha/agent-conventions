# React 컨벤션

## 목적
이 문서는 여러 프로젝트에서 재사용할 수 있는 React 및 TSX 작성 기준을 정의합니다. 컴포넌트 경계, 타입 선언, 이벤트 흐름, 데이터 처리, helper 분리 기준을 일관되게 유지하는 것이 목적입니다.

## 핵심 원칙
- 소유 경계를 분명히 합니다. 공용 UI는 범용적으로 유지하고, 화면 전용 오케스트레이션은 화면 가까이에 둡니다.
- 축약보다 명시성을 우선합니다. 타입과 데이터 출처가 코드에서 바로 드러나야 합니다.
- 표시용 파생값은 실제로 사용하는 렌더링 경로 가까이에 둡니다.
- 조기 공용화를 피합니다. 재사용 또는 명확한 계약이 있을 때만 추출합니다.
- 불필요한 수동 메모이징보다 기본적인 React 렌더링 모델과 컴파일러 최적화를 먼저 믿습니다.

## 파일과 소유 경계
- 파일명은 `kebab-case`를 사용합니다.
- barrel export는 피하고 실제 파일 경로를 직접 import 합니다.
- 화면 전용 컴포넌트, 상수, helper는 해당 화면 근처 또는 전용 로컬 폴더에 둡니다.
- 공용 프레젠테이셔널 컴포넌트는 view 책임에 집중하고 도메인 로직은 상위로 위임합니다.
- 공용 오케스트레이션 컴포넌트는 여러 화면에서 반복되는 경우에만 상태, 훅, view 조합을 담당합니다.

## 타입 선언 규칙
- 재사용 가능한 함수 타입이 있으면 매개변수 타입보다 함수 변수 타입 선언을 우선합니다.
- props callback 구현 시 시그니처를 다시 쓰기보다 기존 시그니처를 재사용합니다.
- 구조가 같은 API 타입이나 도메인 타입을 새로 만들지 말고 재사용합니다.
- 미사용 매개변수도 `_` 접두사로 명시합니다.

## 컴포넌트 작성 규칙
- 가능한 한 이름 있는 컴포넌트와 helper를 사용합니다.
- 범위가 작고 지역적인 값 집합은 enum보다 union 또는 객체 리터럴을 먼저 검토합니다.
- JSX 안의 핸들러는 단순 위임이나 인자 바인딩 정도로만 유지합니다.
- 비동기 처리, 분기, navigation, mutation orchestration은 이름 있는 핸들러로 분리합니다.
- JSX나 훅 인자를 만들기 위해 화면 상단에서 큰 명령형 조립을 하지 않습니다.
- helper는 실제 재사용, 계약 경계, 복잡도 증가가 있을 때만 분리합니다.

## 상태와 원격 데이터
- 데이터의 수명주기와 공유 범위에 맞는 가장 작은 상태 도구를 선택합니다.
- 권한, 세션, 화면 간 공유 상태는 중복 로컬 파생 대신 명시적인 공용 store에 둡니다.
- 원격 데이터 변형은 fetch 경계에 가깝게 둡니다. 예를 들어 query `select`나 좁은 매핑 helper를 우선합니다.
- 데이터 출처를 보존합니다. 넓은 구조분해로 props, store, response 출처를 흐리지 않습니다.
- `??`, `||` 같은 넓은 폴백으로 결측값을 무심코 숨기지 않습니다.
- 로딩/펜딩 UI는 실제 사용자 경험상 필요할 때만 의도적으로 렌더링합니다.

## 주석과 JSDoc
- export 되는 컴포넌트, 훅, helper, 타입 중 이름만으로 계약이 충분히 드러나지 않으면 JSDoc을 추가합니다.
- 외부 연동 또는 I/O 경계에는 `@description`을 사용합니다.
- 내부 handler, effect, helper에는 `@summary`를 사용합니다.
- 인라인 주석은 코드가 무엇을 하는지가 아니라 왜 필요한지 설명합니다.

## 리뷰 체크리스트
- 공용 책임과 화면 전용 책임이 깔끔하게 분리되었는가
- 핵심 핸들러 흐름이 JSX에 숨어 있지 않은가
- helper 분리가 보기 좋음이 아니라 재사용이나 복잡도 경계를 근거로 이루어졌는가
- 원격 데이터와 store 값의 출처가 사용 위치에서 여전히 보이는가
- 옵셔널 값이나 결측 상태가 의도적으로 드러나는가

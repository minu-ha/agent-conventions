# CSS 컨벤션

## 목적
이 문서는 여러 프로젝트에서 재사용할 수 있는 CSS 작성 기준을 정의합니다. 클래스 네이밍, selector 구조, TSX와 CSS의 연결 방식, 서드파티 DOM 스타일링을 예측 가능하게 유지하는 것이 목적입니다.

## 핵심 원칙
- 클래스 이름만 봐도 소유자가 드러나야 합니다.
- selector는 얕게 유지해 변경 영향 범위를 좁힙니다.
- 임의 변형 클래스보다 명확한 상태 modifier를 사용합니다.
- 서드파티 DOM은 로컬 wrapper를 기준으로 제한적으로 스타일링합니다.

## 네이밍
- route, 컴포넌트, 로컬 모듈 등 소유자 기준의 안정적인 네임스페이스를 사용합니다.
- 권장 패턴은 `<owner>__element--modifier`입니다.
- `element`와 `modifier`는 역할 기반으로 짓습니다. `container`, `wrapper`, `box` 같은 포괄적인 단어에 의미를 다 맡기지 않습니다.
- 같은 프로젝트 안에서 소유자 네임스페이스는 고유해야 합니다.

## TSX에서의 클래스 조합
- `clsx` 또는 `classnames` 같은 클래스 조합 helper를 사용합니다.
- 기본 element 클래스 1개와 필요한 상태 modifier 조합을 우선합니다.
- modifier는 `active`, `selected`, `disabled`, `error`처럼 상태를 나타낼 때만 사용합니다.
- 구조 차이, 간격 차이, 레이아웃 차이를 임의 modifier로 표현하지 말고 다른 element나 wrapper로 분리합니다.

## Wrapper 스타일링
- 디자인 시스템 래퍼나 서드파티 위젯을 감싸는 프로젝트에서는 로컬 wrapper를 통해 스타일링하는 방식을 우선합니다.
- 로컬 root 클래스 없이 깊은 override에 의존하지 않습니다.
- 래퍼 컴포넌트가 자체 prop 타입을 공개하면 원본 라이브러리 prop보다 그 래퍼 타입을 우선합니다.

## Selector 구조
- selector는 기본적으로 플랫하게 유지합니다.
- 자기 자신 상태, 직접적인 하위 DOM 상태, 꼭 필요한 서드파티 내부 DOM 타겟팅에 한해서만 제한적 nested를 허용합니다.
- DOM 구조 우연성에 기대는 깊은 descendant chain은 피합니다.

## 값과 토큰
- 색상, 간격, 타이포그래피, 크기처럼 공유되는 값은 토큰이나 CSS 변수로 관리합니다.
- CSS 변수가 비어 있을 수 있는 경우에는 필요한 위치에 의도적인 fallback을 둡니다.
- 레이아웃, 간격, 인터랙션 값을 반복 리터럴로 흩뿌리지 않고 읽기 쉬운 위치에 모읍니다.

## 파일 배치
- CSS는 소유한 컴포넌트, 화면, route 가까이에 둡니다.
- route 레벨 스타일과 route 로컬 컴포넌트 스타일은 명확히 분리합니다.
- 주석은 최소화하되, 예외나 특별한 selector가 필요한 이유는 남깁니다.

## 리뷰 체크리스트
- 소유자 네임스페이스가 고유하고 추적 가능한가
- modifier가 상태를 표현하고 있는가
- selector 구조가 얕고 로컬 소유 범위 안에 있는가
- 서드파티 스타일링이 wrapper 아래에서 명시적으로 이뤄지는가
- 공유되는 값이 토큰이나 CSS 변수로 관리되는가

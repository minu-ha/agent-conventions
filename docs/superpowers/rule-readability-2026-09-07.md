# 한국어와 가독성 개선 결과

2026-09-07, 이전 품질 개선이 반영된 `main` 작업 트리에서 규칙 128개를 검토하고 124개를 다듬었다.
규칙의 뜻과 적용 조건을 유지하면서 한국어 표현을 고치고, 긴 설명을 조건별 표로 재구성했다.

`korean-language`라는 단일 스킬은 로컬에서 찾지 못했다.
대신 저장소에 설치된 `grammar-checker`, `humanizer`, `style-guide`로 문법·표현·문체를 검토했다.

## 분량과 구성

| 스킬 | 검토 / 수정 | 설명 줄 수 | 설명 문자 수 | 표가 있는 규칙 |
| --- | ---: | ---: | ---: | ---: |
| CSS | 34 / 34 | 619 → 433 | 27,832 → 23,965 | 25 → 31 |
| React | 52 / 50 | 877 → 670 | 40,378 → 35,035 | 27 → 46 |
| TypeScript | 42 / 40 | 958 → 669 | 45,563 → 34,070 | 28 → 39 |
| 합계 | 128 / 124 | 2,454 → 1,772 | 113,773 → 93,070 | 80 → 116 |

설명 문자 수는 **18.2%**, 줄 수는 **27.8%** 줄었다.
표는 91개에서 173개로 늘었고, 기존 텍스트 구조도 32개는 유지했다.
설명이 30줄을 넘는 규칙은 16개에서 1개로 줄었다.

측정 대상은 첫 `Incorrect` 앞의 Markdown 설명이다.
frontmatter·영어 제목·Impact·공백 줄·코드 예제는 제외하고 표의 각 행은 한 줄로 센다.
문자 수에는 Markdown 표기와 규칙 참조 ID가 포함된다. 읽는 시간이나 이해도를 측정한 수치는 아니다.

## 실제 HTML 확인

현재 뷰어는 표와 텍스트 코드 블록을 지원하고 Mermaid는 지원하지 않는다.
본문의 판단은 표로 보여 주고, 텍스트 구조도는 기존 `Correct` 예제에 유지했다.
규범을 예제로만 옮겨 생성 계약에서 빠뜨리는 변경은 하지 않았다.

1280×900 화면에서 세 스킬의 설명을 모두 펼쳐 **표 173개**를 확인했다.
표 열 개수 불일치와 설명 영역의 가로 넘침은 없었다.

Biome 설명 영역은 같은 화면 조건에서 **1780px → 1354px**, 약 **23.9%** 낮아졌다.
중간 확인에서는 공백 없는 코드 이름 나열이 한 열을 차지해 오히려 높이가 커지는 문제를 발견했다.
코드 식별자 사이에 쉼표와 공백을 넣어 해결하고, 이 작성 기준도 기여 문서에 추가했다.

## 의미 보존과 최종 검증

- 이전 작업 트리와 비교해 영어 제목·라우팅 조건·규칙 관계를 보존했다.
- 기존 코드 펜스 512개의 내용이 동일하다. 한국어 예제 라벨은 필요한 곳만 다듬었다.
- 독립 검토자가 압축한 규칙 5개를 대조했다. `Partial`·`Required` 조건의 모호함과 배열 반전을 절대 금지로 바꾼 문장을 발견해 원래 뜻으로 보완했다.
- 이전 문장을 정확히 찾던 테스트 9개는 같은 판단을 새 문구로 검사하도록 갱신했다. 테스트 수와 라우팅 시나리오는 유지했다.
- `validate` → `build` → `check:generated:all`, 뷰어 재생성을 완료했다.
- `check:artifacts`, 타입 검사, Biome, `git diff --check`를 통과했다.
- 전체 회귀 테스트 **152개 통과, 실패·건너뜀 0개**.

전체 라우팅 시나리오를 실제 에이전트로 재실행한 행동 인증은 별도로 수행하지 않았다.
변경은 `main` 작업 트리에 반영했으며 커밋·푸시는 하지 않았다.

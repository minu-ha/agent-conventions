# 컨벤션 스킬 품질 개선 계획

**목표:** CSS·React·TypeScript 규칙의 설명과 예제가 실제 동작을 정확히 가르치도록 고친다.

**작업 범위:** 사용자가 승인한 현재 `main`에서 정본을 수정한다. 규칙별 적용 조건과 라우팅 오라클을 함께 검토하고 생성물은 빌드로 갱신한다.

**검증 도구:** 저장소의 validate, build, generated/handbook/viewer 검사, TypeScript, Biome, 기존 회귀 테스트를 사용한다. 기술적 주장은 공식 문서와 작은 재현으로 확인한다.

## 판단 기준

- 예제의 입력·출력·상태·공개 계약이 설명과 일치하는지 확인한다.
- 규칙의 의도와 무관한 동작 차이를 전후 예제에 섞지 않는다.
- 강제 조건, 권장 사항, 기술적 사실을 구분한다.
- 분리는 독립된 적용 조건과 판단이 있을 때, 병합은 같은 조건에서 같은 판단을 반복할 때 한다.
- 새 섹션은 기존 섹션에 속하지 않는 규칙 묶음이 있을 때만 추가한다.
- 적용 시나리오뿐 아니라 비슷하지만 적용되지 않는 사례도 확인한다.
- 기존 이름 규약과 라이브러리 선택 등 팀이 명시적으로 정한 정책은 유지한다.

## 검증의 한계

라우팅 오라클의 정적 검사는 선언한 규칙 관계와 예상 선택 목록의 일관성을 확인한다.
실제 에이전트가 모든 요청에서 같은 규칙을 선택한다는 행동 인증과는 구분한다.
수정한 경계 사례를 별도로 검토하되 전체 행동 인증을 새로 완료했다고 보고하지 않는다.

결과와 검증 근거는 [품질 개선 결과](../skill-quality-review-2026-09-07.md)에 기록했다.

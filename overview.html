이 레포는 팀 코딩 컨벤션을 AI coding agent 가 읽는 skill pack 으로 관리합니다. 규칙 자체보다 규칙이 어떻게 불려 나오는지가 이 프로젝트의 핵심이라, 아래 세 장의 흐름도가 전체 구조입니다.

사람이 고치는 정본 build 생성물 검증 · 도구 분기 ┄┄▶ 되돌아가는 루프
01

실행 흐름

프롬프트 한 줄에서 완료까지

에이전트는 규칙을 통째로 읽지 않습니다. 무엇을 바꿨는지 판정하고, 필요한 것만 골라 읽고, 새로 걸리는 게 없을 때까지 되돌아가 다시 훑습니다. 점선 화살표 세 개가 그 되돌아가는 경로입니다.

되돌아가는 루프가 세 개인 이유 — ① 규칙끼리 서로를 끌어오고(03 참고), ② 작업 도중 범위가 늘어날 수 있고, ③ 마무리 리뷰에서 위반이 나오면 고치고 다시 확인합니다. 이 반복은 더 이상 새로 걸리는 게 없을 때 멈춥니다.

이 구조 덕분에 세 handbook 을 통째로 읽던 35,242 토큰이 실제 경로에서는 중앙값 9,070 토큰으로 줄어듭니다 (1회 로드 −80.3%, 세 단계 누적 −71.2%). 고정한 tiktoken 0.11.0 · o200k_base 실측이며 npm --prefix package run measurement:tokens 로 재현합니다. skill 파일이 context 에 차지하는 크기이고, 에이전트 총 실행 토큰이나 비용에 대한 주장은 아닙니다.

02

어떤 스킬이 어떤 스킬을 켜는가

metadata.json 의 실제 엣지

스킬 하나를 켜면 관련된 것이 따라 켜집니다. 프로젝트 AGENTS.md 에는 owner 스킬 하나만 적어도 되는 이유입니다.

required 는 항상 함께, conditional 은 조건이 맞을 때만 켭니다. 순수 CSS 작업이면 typescript 는 켜지지 않고, 순수 TypeScript 면 react · css 가 켜지지 않습니다. extends 는 아직 progressive 로 옮기지 않은 스킬의 호환 관계입니다.

03

규칙끼리도 서로를 부른다

루프가 도는 진짜 이유

규칙 하나가 Selected 되면 다른 규칙을 강제로 끌고 들어옵니다. 그 대상이 다른 스킬에 있으면 그 스킬을 켜고 인덱스를 처음부터 다시 훑어야 합니다. 이것이 01 의 첫 번째 루프가 존재하는 이유입니다.

현재 requiresSelected 17 개(react 11 · typescript 3 · css 3), reviewWith 33 개(react 23 · typescript 5 · css 5) 의 엣지가 있습니다. reviewWith 는 방향이 있고 역방향으로 추론하면 안 됩니다 — 실제 평가에서 이걸 잘못 추론해 12 개 run 이 막힌 적이 있습니다.

05

유지보수

고치고 안전하게 반영하기
생성물은 고치지 않습니다

AGENTS.md · RULES_INDEX.md · contracts/*.md 는 build 결과물입니다. 직접 고치면 다음 build 에서 덮어써지고 check:generated 에서 실패합니다. 항상 rules/*.md 를 고치세요.

STEP 1고친다 rules/*.md — 필요하면 metadata.json · SKILL.md
STEP 2라우팅 갱신 appliesWhen 과 routing-evals.json 의 기대 선택 목록
STEP 3검증 · 생성 validate → build
STEP 4동기화 확인 check:generated · check:handbooks
STEP 5테스트 test — 125 개
# 처음 한 번
npm --prefix package install

# 스킬 하나 — validate + build
npm --prefix package run dev:react

# 전체
npm --prefix package run validate -- --all
npm --prefix package run build -- --all
npm --prefix package run check:generated:all
npm --prefix package run check:handbooks:all
npm --prefix package run test

고치려는 규칙이 여러 프레임워크 공통이면 companion 스킬에 둡니다. generic TypeScript 규칙이면 skill/typescript 를 우선하고, 프레임워크 고유 제약이면 해당 스킬의 local rule 로 둡니다.
